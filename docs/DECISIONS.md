## Offen (Ideen für später, nicht umsetzen)

- Zutaten: Die Auswahl von Quelle und Ziel beim Zusammenführen sind normale Auswahlfelder. Bei mehreren hundert Zutaten wäre der `IngredientPicker` dort bequemer.
- Zutaten: Legt der Picker eine Zutat an, deren Name nur bei einer archivierten Zutat vorkommt, bietet er die archivierte als „vorhanden“ an. Selten, aber Paket 06 sollte archivierte Treffer nicht in Rezepte übernehmen.
- Zutaten: Die Liste lädt alle Zutaten auf einmal und filtert auf dem Server. Reicht für einige hundert, danach paginieren.

- Lieferanten und Warengruppen: `name` ist in der Datenbank `text unique`, also unterscheidet es Groß und Kleinschreibung („Obst“ und „obst“ gehen beide). Bei Bedarf per neuer Migration auf `citext` oder einen Index auf `lower(name)` umstellen.
- Ohne eigenen SMTP (Mail Limit) können Einladungen nicht verschickt werden. Denkbar wäre bis dahin ein Button „Anmeldelink kopieren“ für den Admin (`generateLink`). Wegen der Rechte bewusst nicht eingebaut.
- Die Admin Formulare brauchen JavaScript. Klickt jemand, bevor die Seite fertig geladen ist, geht eine normale Anfrage raus und nichts wird gespeichert.

- `npm audit` meldet 5 Schwachstellen (hoch) in `braces` über `eslint-config-next`. Betrifft nur das Linten in der Entwicklung, nicht die ausgelieferte App. Beobachten, ob `eslint-config-next` das behebt.
- Seed einspielen: `npx supabase db push --include-seed` (db push allein spielt den Seed nicht ein).
- Standard-Favicon von Next noch vorhanden, wird mit Paket 15 (PWA-Icons) ersetzt.
